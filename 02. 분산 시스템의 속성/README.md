# 02. 분산 시스템의 속성

분산 시스템 설계는 일관성, 가용성, 파티션 허용성, 지연 시간, 내구성, 신뢰성, 장애 허용성, 확장성이라는 속성들 사이에서 균형을 잡는 일이다. 어느 하나를 끌어올리면 다른 하나를 양보해야 하는 트레이드오프가 곳곳에 있으며, 요구 사항에 맞게 이들을 조율하는 것이 핵심이다.

## 2.1 호텔 객실 예약 시스템으로 살펴보는 분산 시스템 예시

이 장은 복제 데이터베이스(db1, db2, db3) 세 개와 연동하는 예약 서비스를 예시로 삼는다. `bookRoom(u1, r1)`이 쓰기, `isRoomAvailable(r1)`이 읽기다. 쓰기 결과를 다른 레플리카에 반영하는 방법은 서버가 직접 모든 레플리카에 쓰는 방식과 데이터베이스 자체 복제 기능에 맡기는 방식으로 나뉜다.

<img width="722" height="429" alt="image" src="https://github.com/user-attachments/assets/46117e95-dc25-4153-8bc6-ce55c3e5477a" />

쓰기 옵션은 지연 시간과 자원 사용량의 트레이드오프로 갈린다.

- 직렬 동기 쓰기(serial sync writes): db1, db2, db3에 순서대로 쓰고 각 응답을 기다린 뒤 클라이언트에 확인한다. 지연 시간이 매우 길다.
- 직렬 비동기 쓰기(serial async writes): db1에 쓰고 응답받으면 즉시 클라이언트에 응답하고 나머지는 비동기로 갱신한다. 지연 시간이 낮다.
- 병렬 비동기 쓰기(parallel async writes): 모든 레플리카를 동시에 갱신하되 일부 응답만 받고 클라이언트에 응답한다. 지연 시간은 낮지만 스레드 자원 사용량이 높다.
- 메시징 서비스(카프카 등)에 쓰기: 메시징 서비스에 기록하고 즉시 응답한 뒤, 소비자가 데이터를 가져가 각 레플리카에 적용한다. 지연 시간이 가장 짧고 쓰기 폭주에도 견딘다.

읽기 옵션은 정확성과 속도의 트레이드오프다.

- 하나의 레플리카에서만 읽기: 빠르지만 오래된 데이터가 반환될 수 있다.
- 일부(과반수) 레플리카에서 읽기: 일관성과 속도 사이에서 균형 잡힌 선택이다.
- 모든 레플리카에서 읽기: 최신 값을 보장하지만 느리다.

## 2.2 일관성

일관성은 데이터가 여러 노드에 복제되고 분산되어 있어도 모든 노드가 항상 동일한 상태와 데이터를 참조하도록 하는 개념이다. 모든 노드가 같은 업데이트 요청에 동일한 순서로 갱신된 데이터를 반환한다.

**강한 일관성**(strong consistency): 모든 노드가 공유 데이터의 업데이트를 동일한 순서로 처리하도록 보장한다. 쓰기 이후의 모든 읽기가 항상 최신 값을 반환하고 시스템이 선형적 상태로 보인다. 분산 트랜잭션, 분산 락, 팍소스나 래프트 같은 알고리즘으로 구현한다. 시스템이 예측 가능하고 직관적이지만, 노드들이 업데이트 순서에 동의할 때까지 기다려야 해 처리 속도나 가용성을 대가로 치른다. 계좌 잔액이나 거래 내역을 다루는 은행과 금융 시스템에 적합하다.

**최종 일관성**(eventual consistency): 일시적인 데이터 불일치는 허용하되 시간이 지나면 모든 레플리카가 결국 동일한 상태에 도달하도록 보장한다. 비동기로 갱신하므로 일정 시간 동안 노드마다 다른 데이터를 가질 수 있고, 이는 네트워크 지연이나 동기화 문제에서 비롯된다. 충돌 해결(conflict resolution), 복제, 가십 프로토콜(gossip protocol), 버전 관리, 조정 알고리즘으로 일관된 상태로 수렴시킨다. 가용성과 확장성이 높고 응답이 빠르며, 네트워크 분할이나 일시적 장애에도 각 노드가 계속 요청을 처리한다. 대신 일시적 불일치를 애플리케이션이 다뤄야 하는 부담이 있다.

선택 기준은 단순하다. 즉각적이고 엄격한 동기화가 필요하면 강한 일관성, 일시적 불일치를 감수하고 가용성과 확장성을 높이려면 최종 일관성이다.

일관성을 정량적으로 다룰 때 세 변수를 쓴다. n은 레플리카 총 개수, r은 읽을 때 참조할 레플리카 수, w는 쓸 때 반영할 레플리카 수다.

정족수 원리: **w + r > n** 을 만족하면 강한 일관성이 보장되고, 그렇지 않으면 최종 일관성이 적용된다. w를 키우면 쓰기가 느려지고 r을 키우면 읽기가 느려지므로, 같은 강한 일관성 안에서도 r과 w를 어떻게 배분하느냐로 읽기와 쓰기 속도의 균형이 달라진다.

<img width="555" height="211" alt="image" src="https://github.com/user-attachments/assets/9e8381ce-66b9-4fbe-a4a1-0644cfe9fa2f" />

예약 시스템이라고 해서 반드시 강한 일관성이 정답은 아니다. 시스템이 항상 이용 가능한 상태를 지키려고 일관성을 약간 포기하고 최종 일관성을 택하는 편이 더 유리할 때도 있다. 이는 가용성과 함께 따져야 하는 선택이다.

## 2.3 가용성

가용성은 장애나 오류가 발생해도 사용자에게 서비스를 지속적으로 제공하는 능력이다. 가용성이 높은 시스템은 내부 문제와 상관없이 언제나 요청에 응답할 준비가 되어 있다. 여러 구성 요소가 서버 장애, 네트워크 문제, 통신 오류에 노출되므로 높은 가용성을 안정적으로 유지하기는 쉽지 않다.

보장 방식.

- 다중화(중복성): 구성 요소나 자원을 여러 개 둔다. 하드웨어 중복성은 전원 공급 장치나 네트워크 연결을 복수로, 소프트웨어 다중화는 프로세스나 서비스를 복수로 준비한다.
- 복제: 데이터를 여러 노드에 복제한다. 액티브-패시브(active-passive)는 한 노드가 주 노드, 나머지가 백업으로 대기하고, 액티브-액티브(active-active)는 여러 노드가 동시에 요청을 처리한다.
- 로드 밸런싱: 작업량을 노드에 고르게 분배해 과부하와 병목을 방지한다.
- 장애 감지 및 복구: 하트비팅, 모니터링, 헬스 체크로 장애 노드를 파악하고 복원하거나 교체한다.
- 장애 전환 및 복귀: 장애가 생기면 백업 노드로 요청을 돌리고(failover), 복구되면 원래 노드로 되돌린다(failback).

가용성을 높이면 복잡성과 자원 소모가 늘고 일관성이나 성능과의 조정이 필요하다.

## 2.4 파티션 허용성

네트워크 파티션은 네트워크 장애로 일부 노드가 시스템의 다른 부분과 연결이 끊겨 통신하지 못하는 상태다. 분산 시스템이 서로 통신할 수 없는 독립된 조각들로 나뉜다. 네트워크 장애, 하드웨어 고장, 버그, 설정 변경, 공격이 원인이 된다. 파티션이 지속되는 동안 한쪽의 쓰기가 다른 쪽으로 전달되지 않아 오래된 데이터가 반환될 수 있고, 지속 시간이 길수록 데이터 불일치와 요청 처리 실패로 이어진다.

파티션 허용성은 네트워크 장애나 파티션이 발생해도 시스템이 계속 정상 작동하는 능력이다. 고립된 노드도 독립적으로 클라이언트 요청을 처리하고 나머지 부분도 평소처럼 동작한다. 장애 시 성능이 급격히 떨어지지 않고 점진적으로 저하되도록 설계해 견고함을 확보한다. 파티션이 생겼을 때 일관성과 가용성 중 무엇을 택할지는 다음 장의 CAP 정리에서 다룬다.

## 2.5 지연 시간

지연 시간은 요청이 들어와 응답이 돌아오기까지 걸리는 시간이며, 데이터가 한 지점에서 다른 지점으로 이동하는 데 걸리는 시간이다. 노드 간 거리, 네트워크 혼잡도, 노드의 처리 시간, 전송 데이터의 크기와 복잡성에 영향을 받는다.

지연 시간을 줄이는 기술.

- 네트워크 최적화: 빠른 연결을 쓰거나 네트워크 홉(hop) 수를 줄이고 혼잡도를 최소화한다. 홉은 데이터가 거치는 중간 지점이며 많을수록 지연이 늘어난다.
- 캐싱: 메모리 캐싱, CDN, 데이터베이스 캐싱으로 자주 쓰는 데이터를 사용자에게 더 가까운 곳에서 제공한다.
- 데이터 지역화: 데이터를 사용자 가까이 배치한다. 데이터 복제, 에지 컴퓨팅(edge computing), 콘텐츠 분산 전략을 활용한다.
- 비동기 통신: 메시지 큐나 이벤트 기반 아키텍처로 컴포넌트 간 결합을 줄이고 병렬, 논블로킹 처리로 지연 영향을 낮춘다.
- 성능 튜닝: 자원을 조정하고 쿼리를 최적화하며 알고리즘과 코드 실행을 개선한다.

지연 시간은 완전히 없앨 수 없다. 분산 시스템은 본질적으로 네트워크 지연이 있는 환경이며, 지연을 극단적으로 줄이려다 보면 일관성이나 장애 허용성에 영향을 준다. 요구 사항과 제약에 맞는 균형이 필요하다.

## 2.6 내구성

내구성은 장애나 오류가 발생해도 저장된 데이터가 손실되지 않도록 보장하는 능력이다. 여러 노드로 구성된 분산 시스템에서는 노드 장애로 데이터 손실이나 손상이 생길 수 있어 특히 중요하다. 데이터를 여러 노드에 복제하면 한 노드가 죽어도 다른 노드에서 복구할 수 있고, 백업으로 심각한 장애에 대비한다. 내구성은 일관성, 가용성과 밀접하다. 여러 곳에 복제해 내구성을 높이면 일관성 유지에 시간이 더 걸리므로 종합적으로 조율해야 한다.

## 2.7 신뢰성

신뢰성은 하드웨어 고장, 네트워크 문제, 애플리케이션 버그, 휴먼 에러 등 다양한 장애에도 시스템이 원래 기능을 꾸준히 제공하는 능력이다. 중복성으로 한 장비가 고장 나도 다른 장비가 대신하게 하고, 오류를 자동으로 감지하고 바로잡으며, 복제와 로드 밸런싱으로 부하를 고르게 나눠 신뢰성을 높인다.

## 2.8 장애 허용성

장애 허용성은 일부 요소가 고장 나거나 네트워크 문제가 생겨도 시스템이 정상 작동을 계속하는 능력이다. 사람이 개입하지 않아도 장애를 자동으로 감지하고 복구하도록 설계한다. 다중화(중복성)로 하나가 고장 나도 다른 것이 역할을 대신하고, 복제로 특정 위치에 장애가 생겨도 다른 위치에서 서비스를 이어 가며, 장애 감지 및 복구 메커니즘으로 응답 없는 노드를 다른 노드나 백업으로 전환한다.

## 2.9 확장성

확장성은 사용자 수나 데이터양이 증가해도 성능과 신뢰성을 유지하면서 더 많은 작업을 처리하는 능력이다. 새 자원을 추가하거나 기존 자원을 최적화하는 것을 포함한다.

**수직 확장성**(vertical scaling, 스케일 업): 개별 노드나 인스턴스의 용량을 늘린다. CPU 성능 향상, 메모리 추가, 저장 용량 확장 같은 하드웨어 업그레이드가 중심이다.

- 장점: 단순성(기존 아키텍처에 최소한의 변경), 소규모 작업에 대한 비용 효율성.
- 단점: 하드웨어 한계점(업그레이드를 계속하면 비용이 급증), 단일 장애점(노드 하나에 의존해 그 노드가 죽으면 전체가 멈춤).

**수평 확장성**(horizontal scaling, 스케일 아웃): 노드나 인스턴스를 추가해 작업을 여러 노드에 분산하고 병렬 처리한다.

- 장점: 성능 증가(노드 추가로 더 많은 처리), 장애 허용성(한 노드가 죽어도 다른 노드가 가용성 유지).
- 과제: 분산 조정(노드 간 협력과 동기화 메커니즘 필요), 데이터 일관성(여러 노드에 분산되어 단일 노드보다 일관성 유지가 어려워 분산 트랜잭션이나 최종 일관성으로 관리).

둘은 양자택일이 아니라 섞어 쓸 수 있다. 선택은 요구 사항, 작업 부하 패턴, 비용, 작업을 효과적으로 분산할 수 있는지에 따라 달라진다. 아키텍처를 모듈화하고 느슨하게 결합해 각 모듈을 독립적으로 추가하거나 제거할 수 있게 만들면 확장성이 올라간다.

## 2.10 요약

분산 시스템 설계는 일관성, 가용성, 파티션 허용성, 지연 시간, 내구성, 신뢰성, 장애 허용성, 확장성을 종합적으로 조율하는 일이다. 모든 노드가 동일한 순서로 같은 업데이트를 처리하도록 일관성을 확보하되, 강한 일관성과 최종 일관성 중 무엇을 택할지가 설계의 갈림길이 된다. 가용성과 파티션 허용성은 다중화, 복제, 장애 복구로 끌어올리고, 지연 시간은 캐싱과 데이터 지역화, 비동기 통신으로 관리한다. 내구성과 신뢰성은 복제와 백업, 다중화로 데이터를 보존하며, 확장성은 수직 확장과 수평 확장의 장단점을 저울질해 결정한다. 결국 한 속성을 강화하면 다른 속성을 양보하게 되는 트레이드오프를 이해하는 것이 분산 시스템 설계의 출발점이다.
