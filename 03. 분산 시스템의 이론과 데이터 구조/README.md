# 03. 분산 시스템의 이론과 데이터 구조

분산 시스템 설계의 이론적 기반이 되는 정리들과 실무에서 널리 쓰는 확률적 자료 구조를 다룬다. 
CAP, PACELC, FLP 불가능성 정리, 비잔티움 장군 문제는 분산 시스템에서 무엇이 가능하고 무엇이 불가능한지의 한계를 알려 주고, 팍소스와 래프트 같은 합의 알고리즘은 그 한계 안에서 여러 노드가 하나의 결정에 도달하는 방법이다. 
일관된 해싱, 블룸 필터, 카운트-민 스케치, 하이퍼로그로그는 적은 메모리로 큰 문제를 푸는 자료 구조다.

## 3.1 CAP 정리

분산 시스템은 일관성(Consistency), 가용성(Availability), 파티션 허용성(Partition tolerance)을 동시에 만족할 수 없다.

분산 시스템에서 네트워크 파티션은 하드웨어 고장, 네트워크 장애, 정기 점검 등으로 불가피하게 발생한다. 파티션이 일어나면 일관성과 가용성 중 하나를 선택해야 한다.

- 일관성 우선(CP): 모든 노드가 동일한 데이터를 유지하지만, 파티션 상황에서 일부 노드는 사용자 요청을 처리하지 못할 수 있다.
- 가용성 우선(AP): 모든 노드가 독립적으로 요청을 처리하지만, 노드마다 서로 다른 데이터 상태를 가질 수 있다.

CAP 정리는 세 속성을 전부 포기하라는 말이 아니라, 파티션 상황에서 일관성과 가용성 중 무엇을 택할지의 비용을 보여 준다. 금융 거래처럼 일관성이 중요하면 CP, 웹 애플리케이션처럼 빠른 응답이 중요하면 AP가 적합하다.

## 3.2 PACELC 정리

CAP의 연장선이다. 파티션(P)이 발생하면 가용성(A)과 일관성(C) 중 하나를 택하고(CAP과 동일), 그 외(E, else, 파티션이 없을 때)에는 지연 시간(L)과 일관성(C) 중 하나를 택한다.

PACELC는 CAP보다 넓은 경우의 수를 포함한다. 파티션이 없어도 지연 시간과 일관성 사이에 선택이 필요하다는 점이 핵심이다. 일관성을 택하면 지연 시간이 늘고, 낮은 지연 시간을 택하면 일관성을 일부 포기한다. 애플리케이션의 정책에 따라 어느 쪽을 감수할지가 달라진다.

합의(consensus)는 분산 시스템에서 서로 다른 서버들이 동일한 상태나 결정을 유지하도록 하는 과정이다. 각 서버가 독립적으로 작동하면 같은 데이터에 대해 다른 결정을 내려 불일치가 생기므로, 합의 알고리즘으로 모든 노드를 동기화해 일관성을 지킨다.

팍소스 알고리즘은 레슬리 램포트가 개발한 합의 알고리즘으로 현대 분산 시스템의 초석이 됐다. 여러 노드가 하나의 값에 합의하도록 한다. 구성 요소는 합의를 시작하고 값을 제안하는 제안자(proposer), 제안을 받아 수용 여부를 알리는 수용자(acceptor), 합의된 값을 최종적으로 받는 학습자(learner)다.

프로토콜은 세 단계로 진행된다.

- 준비 단계: 제안자가 겹치지 않는 고유한 제안 번호를 골라 수용자들에게 준비 요청을 보낸다. 수용자는 자신이 수용한 제안 중 가장 높은 번호를 응답한다.
- 수용 단계: 응답을 받은 제안자가 제안 번호와 값을 담아 수용 요청을 보낸다.
- 합의점 도달: 다수의 수용자가 수용하면 값이 선택되고 학습자에게 전달된다.

핵심은 제안 번호로 우선순위를 정하는 것이다. 수용자는 자신이 본 가장 높은 번호를 기억하고 더 낮은 번호의 제안은 거부한다. 합의에 실패해도 다음에 더 높은 번호로 재시도하므로 결국 하나의 합의에 도달한다.

고려 사항은 장애 처리(일부 노드 장애에도 작동), 확장성(노드가 늘면 통신 부담으로 성능 저하), 복잡성(정확히 이해하고 구현하기 어려움)이다.

변형으로 값 여러 개에 연속으로 합의하며 준비와 수용 단계의 반복을 피하는 멀티 팍소스(multi-paxos), 준비 단계를 건너뛰어 메시지 수를 줄이는 패스트 팍소스(fast-paxos), 준비와 수용 단계를 통합해 단순화한 심플 팍소스(simple-paxos)가 있다. 분산 데이터베이스, 분산 파일 시스템(GFS, HDFS), 상태 기계 복제에 쓰인다.

래프트 알고리즘은 팍소스보다 이해하기 쉽고 구현 난이도가 낮아 대안으로 많이 쓰인다. 하나의 합의 문제를 리더 선출, 로그 복제, 안정성이라는 하위 문제로 나누어 푼다. 팍소스와 달리 지정된 리더가 있다.

구성 요소는 합의 과정을 관리하고 로그 복제를 지시하는 리더(leader), 리더의 로그를 복제하고 요청에 응답하는 추종자(follower), 리더 실패 시 투표를 요청해 선출을 시작하는 후보자(candidate)다.

프로토콜은 리더 선출(후보가 과반수 투표를 받으면 리더가 됨), 로그 복제(리더가 클라이언트 요청을 로그에 추가해 추종자에 복제하고 추종자는 자신의 상태 기계에 적용), 안정성과 일관성(특정 규칙으로 불일치를 막고 최신 로그 항목만 적용)으로 이뤄진다. 고려 사항은 리더 가용성(리더 장애 시 신속한 재선출), 확장성, 장애 허용성이다.

DynamoDB 같은 분산 데이터베이스, 구글 파일 시스템, 클러스터 관리와 서비스 디스커버리(아파치 주키퍼), 합의 기반 알고리즘(구글 스패너), 클라우드 인프라 관리(넷플릭스)에 쓰인다. 다만 래프트는 노드가 멈추는 장애는 처리하지만 노드가 잘못 작동하거나 악의적으로 행동하는 경우는 다루지 못한다. 이는 비잔티움 장군 문제로 이어진다.

## 3.3 비잔티움 장군 문제

일부 노드가 오류를 내거나 거짓 정보를 전달할 때 나머지가 어떻게 신뢰할 수 있는 합의에 도달하는지를 묻는 사고 실험이다. 적의 도시를 포위한 장군들이 전령으로만 소통하는데 일부가 배신자일 수 있는 상황에 비유한다. 전령이 가로채일 수 있고, 누가 배신자인지 구별할 수 없으며, 배신자들이 공모할 수 있다는 점이 합의를 어렵게 한다.

해결 조건은 충성스러운 장군이 과반수여야 하고, 전체 장군 수 N에 대해 배신자 수 f가 (N-1)/2 미만이어야 한다는 것이다. 즉각 합의는 불가능하고 시간이 필요하다. 해결 방식으로 투표 알고리즘(3분의 2 이상 찬성), 반복 서명 방식, 쿼럼 방식, 타임아웃과 확인 절차, 무작위 선택 방식이 있다. 공통 핵심은 투표로 배신자를 색출하고 배신자를 제외한 나머지만으로 합의할 수 있도록 중복성을 확보하는 것이다.

비잔티움 장애는 일부 노드가 예측할 수 없고 신뢰할 수 없는 행동을 보이는 상황이다. 소프트웨어 버그, 하드웨어 고장, 악의적 공격으로 발생하며, 거짓이거나 모순된 정보를 만들어 내 문제 노드를 식별하고 격리하기 어렵다.

비잔티움 장애 허용성은 일부 노드가 고장 나거나 악의적으로 행동해도 시스템이 올바르게 기능하며 합의에 도달하는 성질이다. 초기 버전은 램포트, 쇼스탁, 피스가 제안했으며, 각 노드가 값을 투표 형식으로 모든 노드에 보내 다수결로 결정하는 방식이었다. 단, 고장 노드가 전체의 3분의 1 미만일 때만 작동하고 모든 노드가 서로 통신해야 해 계산과 통신 비용이 컸다.

최신 비잔티움 장애 허용성은 실용적 비잔티움 장애 허용 알고리즘(PBFT)으로 개선됐다. 통신 비용을 줄이고 대규모 네트워크에서 효율적으로 동작하며, 비트코인과 이더리움 같은 블록체인의 운영에 중요한 역할을 한다.

## 3.4 FLP 불가능성 정리

피셔(Fischer), 린치(Lynch), 패터슨(Paterson)이 1985년 증명했다. 완전 비동기 환경에서 노드 하나라도 고장 나면 모든 정상 노드가 동일한 결정을 내리도록 보장하는 알고리즘은 존재할 수 없다.

전제 조건은 비동기성(메시지 지연과 프로세스 속도에 제한이 없음), 프로세스 장애(전체 중 일부가 고장 날 수 있음), 유한한 단계(각 프로세스는 정해진 유한한 단계만 수행)다.

증명의 핵심은 비동기 시스템에서 느리게 응답하는 프로세스와 실제로 고장 난 프로세스를 구별할 방법이 없다는 점이다. 이 모호함 때문에 장애 허용성, 합의, 종료를 동시에 달성할 수 없고 셋 중 둘만 가질 수 있다. 한계를 넘으려면 메시지 지연에 시간 범위를 두거나(동기적 가정), 확률 알고리즘을 쓰거나, 무작위 요소나 시간 동기화를 도입하거나, 리더나 조정자 역할을 두는 방법을 쓴다.

## 3.5 일관된 해싱

데이터를 여러 노드에 분배하면서 노드를 추가하거나 삭제할 때 옮겨야 하는 데이터를 최소화하는 방식이다. 확장성과 장애 허용성을 높인다.

모듈로 해싱은 데이터 키의 해시 값을 노드 개수로 나눈 나머지로 노드를 정하는데, 노드 수가 고정되어 있어 노드를 추가하거나 삭제하면 해시 함수가 바뀌면서 많은 데이터를 다시 매핑하고 재분배해야 한다. 이는 시간과 자원을 많이 소모하고 가용성을 떨어뜨린다.

일관된 해싱은 데이터 키와 노드 식별자를 공통 해시 공간에 매핑하며, 이 공간은 보통 원형 링으로 표현된다. 데이터 키를 링 위에 놓고 시계 방향으로 이동하다 처음 만나는 노드(담당 노드)가 그 데이터를 맡는다. 노드를 추가하거나 삭제할 때 인접한 노드로 일부 데이터만 다시 매핑하면 되므로 데이터 이동량이 제한된다.

단순한 링에는 두 가지 문제가 있다. 요청이 노드에 고르게 분배되지 않을 수 있고, 한 노드가 다운되면 시계 방향의 다음 노드가 작업을 떠안아 과부하로 연쇄 다운이 일어날 수 있다. 이를 개선하려고 서버마다 가상 지점 여러 개를 링의 여러 위치에 분산한다. 그러면 한 서버가 다운돼도 그 서버의 지점들만 사라지고 요청이 나머지 서버에 거의 균등하게 분배된다.

## 3.6 블룸 필터

메모리를 적게 쓰면서 특정 요소가 집합에 속하는지 빠르게 확인하는 확률적 자료 구조다. 고정 크기의 비트 배열과 여러 해시 함수로 구성한다.

처음에 비트 배열을 모두 0으로 둔다. 요소를 추가할 때는 여러 해시 함수로 나온 위치의 비트를 1로 설정한다. 조회할 때는 같은 해시 함수로 위치의 비트를 검사한다. 하나라도 0이면 그 요소는 집합에 없는 것이 확실하고, 모두 1이면 포함될 가능성이 높다.

블룸 필터는 거짓 양성(false positive), 즉 실제로는 없는 요소를 있다고 잘못 판단하는 경우가 있을 수 있다. 다른 요소들이 우연히 같은 비트들을 1로 만들어 두었을 수 있기 때문이다. 반면 거짓 음성, 즉 있는 요소를 없다고 판단하는 경우는 발생하지 않는다. 거짓 양성은 비트 배열 크기나 해시 함수 개수를 늘려 줄일 수 있지만 그만큼 메모리와 계산량이 늘어난다.

포함 여부 검사(멤버십 테스트), 캐싱, 데이터베이스 최적화(없는 데이터를 걸러 불필요한 디스크 읽기 차단), 네트워크 라우팅, 중복 제거에 쓰인다.

## 3.7 카운트-민 스케치

데이터 스트림에서 요소의 빈도를 추정하는 확률적 자료 구조다. 메모리를 적게 쓰며 대규모 실시간 스트림 처리에 효과적이다.

해시 함수 개수만큼의 행과 정해진 길이의 열로 이뤄진 이차원 배열 카운터로 구성한다. 요소가 들어오면 여러 해시 함수로 각 행의 위치를 정해 해당 카운터를 1씩 증가시킨다. 특정 요소의 빈도를 조회할 때는 그 요소가 매핑되는 각 행의 셀 값들 중 최솟값을 사용한다.

여러 요소가 같은 셀에 매핑되는 충돌이 생기면 값이 실제보다 크게 측정되므로 과대 추정이 발생할 수 있다. 최솟값을 취하는 것이 이 과대 추정을 완화한다. 카운터 수와 해시 함수 개수를 늘리면 정확도가 올라가지만 메모리와 계산 비용이 증가한다.

빈도 추정, 네트워크 트래픽 분석, 웹 분석, 분산 시스템의 요청 빈도 모니터링, 데이터 스트림 처리에 쓰인다.

## 3.8 하이퍼로그로그

집합 내 중복되지 않는 요소 개수, 곧 카디널리티(cardinality)를 매우 적은 고정 메모리로 추정하는 확률적 알고리즘이다. 필리프 플라졸레(Philippe Flajolet)가 개발했다.

원리는 각 요소를 해싱한 뒤 해시 값의 이진 표현에서 끝에 연속된 0의 최대 길이 L을 보는 것이다. 동전 던지기에서 뒷면(0)이 L번 연속으로 나오려면 평균 2^(L+1)번 던진 셈이듯, 끝자리 0이 L번 이어졌다면 고유 요소가 대략 2^(L+1)개 있다고 추정한다.

정확도를 높이려고 해시 값을 버킷 m개로 나눠 각 버킷의 끝자리 0 최대 개수를 구한 뒤, 산술 평균 대신 조화 평균을 써서 이상치의 영향을 줄인다. 이름의 'Log'는 조화 평균(harmonic mean) 계산을 가리킨다. 메모리 효율이 뛰어나 방문자 10억 명을 추정하는 데도 카운터 열 개, 10바이트면 충분하다.

데이터베이스 시스템, 네트워크 트래픽 분석, 웹 분석, 빅 데이터 처리에서 중복 없는 실제 개수를 측정하는 데 쓰이며, 메모리가 제한된 분산 시스템이나 스트리밍 환경에서 빠른 근사치가 필요할 때 유용하다.

## 3.9 요약

분산 시스템의 이론적 기반과 자료 구조를 다뤘다. CAP과 PACELC는 일관성, 가용성, 지연 시간 사이의 상충 관계를 보여 주고, 팍소스와 래프트는 장애 속에서도 여러 노드의 합의를 이끄는 알고리즘이다. 비잔티움 장군 문제는 악의적 노드가 섞인 환경에서 합의의 어려움을, FLP 불가능성 정리는 단 하나의 장애가 있는 비동기 시스템에서 합의가 근본적으로 불가능함을 드러낸다. 자료 구조로는 노드 변경 시 데이터 이동을 최소화하는 일관된 해싱, 포함 여부를 검사하는 블룸 필터, 빈도를 추정하는 카운트-민 스케치, 카디널리티를 추정하는 하이퍼로그로그를 살펴봤다. 이 정리와 알고리즘, 자료 구조에 대한 이해가 다음 장에서 실제 구성 요소를 설계하는 토대가 된다.
