# 01. 시스템 설계의 기본

시스템 설계는 특정 요구 사항을 충족하기 위해 시스템의 아키텍처, 구성 요소, 인터페이스, 기타 특성을 정의하는 과정이다. 상위 수준의 아키텍처 설계에서 시작해 하위 수준의 상세 설계로 내려가는 두 층위로 진행된다. 잘 설계된 시스템은 성능과 사용자 경험을 끌어올리고 보안을 강화하며 개발 비용과 시간을 절감한다.

## 1.1 시스템 설계의 정의

**시스템 설계**: 특정 요구 사항을 이루기 위해 시스템의 아키텍처, 구성 요소, 인터페이스, 기타 특성을 정의하는 과정이다.

**소프트웨어 시스템**: 특정 작업을 수행하려고 함께 동작하는 컴포넌트, 모듈, 프로그램의 집합이다. 데이터 관리, 트랜잭션 처리, 최종 사용자 서비스 제공 같은 기능을 수행한다. 단순 프로그램처럼 간단할 수도, 여러 컴퓨터와 네트워크에 걸친 분산 시스템처럼 복잡할 수도 있다.

**분산 소프트웨어 시스템**: 여러 독립적인 컴포넌트나 프로세스, 노드가 서로 통신하며 하나의 공동 목표를 달성하려고 동작한다. 모든 구성 요소가 한 기기에 모인 중앙 집중형과 달리 지리적으로 다른 위치의 여러 기기와 네트워크에 걸쳐 있다. 통신 수단으로 원격 프로시저 호출(RPC), 메시지 패싱(message passing), 발행/구독 모델(publish/subscribe)을 쓴다. 확장성, 가용성, 장애 허용이 중요한 대규모 애플리케이션에 사용한다. 예로는 클라우드 컴퓨팅 플랫폼, P2P 네트워크, 분산 데이터베이스, 콘텐츠 전송 네트워크(CDN)가 있다.

**시스템 설계의 이해**: 아키텍처, 컴포넌트, 모듈, 인터페이스, 상호 작용을 정의해 기능 요구 사항과 비기능 요구 사항을 모두 채우는 과정이다. 요구 사항을 구조, 구현, 유지 보수 방식을 설명하는 청사진(blueprint)이나 계획으로 변환하는 작업이다. 좋은 설계의 목표는 이해와 유지 보수, 확장이 쉽고 성능과 확장성, 신뢰성, 보안 요구 사항을 만족하며, 요구 사항과 실행 환경이 바뀌어도 유연하게 대응하는 것이다.

설계는 보통 여섯 단계를 거친다.

- 요구 사항 분석: 기능과 비기능 요구 사항을 분석하고 데이터 조회와 저장 패턴을 파악한다.
- 상위 수준 아키텍처 설계: 컴포넌트, 모듈, 인터페이스 등 전반적인 구조를 정의한다.
- 하위 수준 상세 설계: 내부 구조와 동작, 알고리즘, 컴포넌트 간 상호 작용을 설계한다.
- 사용자 인터페이스 설계: API로 백엔드와 통신하는 UI를 상위 수준에서 정의한다.
- API 설계: 프런트엔드가 백엔드와 상호 작용할 적절한 API를 정의한다.
- 데이터베이스 설계: 데이터 구조와 저장 메커니즘을 정한다. 파일 저장소부터 관계형, NoSQL까지 선택지가 다양하다.

설계 과정의 결과물은 아키텍처 다이어그램과 상세 설계 문서, API와 UI 프로토타입을 정의한 설계 문서이며, 구현의 길잡이 역할을 한다.

## 1.2 시스템 설계의 다양한 유형

시스템 설계는 상위 수준의 아키텍처 설계와 하위 수준의 상세 설계, 두 유형으로 나뉜다.

상위 수준 설계에서 고려할 항목은 시스템 아키텍처, 데이터 흐름, 확장성, 장애 허용 시스템이다.

아키텍처는 다음 패턴으로 나뉜다.

- 모놀리식(monolithic): 모든 구성 요소를 결합한 하나의 독립적 애플리케이션.
- 클라이언트-서버(client-server): 클라이언트가 하나 이상의 서버에 서비스를 요청하는 분산 아키텍처.
- 마이크로서비스(microservices): 네트워크로 통신하는 작고 독립적인 여러 서비스로 구성된 아키텍처.
- 이벤트 주도(event-driven): 비동기 이벤트나 메시지로 각 구성 요소가 상호 작용하는 시스템.

아키텍처 선택 시 확장성, 유지 보수성, 신뢰성, 지연 시간을 함께 따진다. 상위 수준 설계는 요구 사항에 가장 적합한 아키텍처를 명확히 고르고, 그 이유와 시스템 목표의 일치 여부를 정의하는 데서 시작된다.

데이터 흐름 설계에서는 데이터 수집, 저장, 처리, 검색을 각각 정한다. 데이터 흐름은 성능과 확장성, 사용성에 직접 영향을 미치므로 각 단계에서 올바른 도구와 방법을 선택해야 한다.

확장성은 성능 저하 없이 늘어나는 작업 부하를 처리하는 능력이며 두 가지로 나뉜다.

- 수직 확장성: CPU, 메모리, 저장소 등 단일 컴포넌트에 자원을 추가한다.
- 수평 확장성: 작업 부하를 여러 컴포넌트나 인스턴스로 분산한다. 클러스터에 서버를 추가하는 식이다.

확장성 설계 시 로드 밸런싱, 캐싱, 데이터베이스 분할, 스테이트리스 서비스를 검토한다.

장애 허용 시스템은 일부 요소에 장애가 생겨도 계속 정상 작동하는 능력이다. 신뢰성이 높고 다운타임이 적다. 복제, 중복성, 점진적 성능 저하, 모니터링, 자가 복구를 신경 써야 한다.

상위 수준 설계는 전체 아키텍처에 중점을 두며 구현 세부나 최적화는 깊이 들어가지 않는다.

하위 수준 상세 설계는 구성 요소의 구현 세부 사항에 중점을 둔다. 성능과 메모리 사용, 코드 유지 보수성을 최적화하는 알고리즘, 데이터 구조, API를 선택하는 작업이 들어간다. 주요 요소는 다음과 같다.

알고리즘은 계산과 데이터 처리, 문제 해결의 단계별 절차다. 시간 복잡도와 공간 복잡도, 둘 사이의 트레이드오프를 고려해 선택한다. 성능 좋은 기기를 비싸게 사기보다 알고리즘을 알맞게 최적화하는 편이 낫다.

데이터 구조는 메모리에서 데이터를 구성하고 관리하는 방식이다. 데이터 접근 방식, 쿼리 성능, 메모리 사용량을 따져 선택한다. 배열, 연결 리스트, 해시 테이블, 트리, 그래프가 많이 쓰인다.

API(Application Programming Interface)는 시스템 내 구성 요소 간 통신 규약이며 모듈화와 관심사의 분리를 가능하게 한다. 일관성, 유연성, 보안, 성능을 고려해 설계한다. 엔드포인트에 버전을 부여하면(예: `/api/v1/users`) 하위 호환성을 보장한다. 새 요구 사항을 v2로 추가하면서 기존 클라이언트는 v1을 그대로 쓰다가 하나씩 v2로 옮기고, 모두 이전하면 v1을 제거하는 식이다.

코드 최적화는 코드의 성능과 가독성, 유지 보수성을 끌어올리는 기법이다. 리팩터링, 루프 언롤링(loop unrolling), 메모이제이션(memoization), 병렬 처리가 있다.

## 1.3 업계에서 시스템 설계가 갖는 중요성

- 요구 사항에 대한 명확한 이해: 설계 과정에서 핵심 기능, 성능, 보안 지침을 자연스럽게 파악한다.
- 협업의 시너지: 상세 설계 단계에 더 많은 팀원이 참여해 소통과 협업 효율이 올라가고, 이해 관계자와의 소통도 원활해진다.
- 설계 검토와 피드백: 팀원과 아키텍트가 검토에 쉽게 참여해 논의와 피드백 반영이 수월하다.
- 높은 확장성: 확장 가능성을 미리 파악해 쉽게 확장하고 축소하는 구조를 설계한다.
- 성능: 다양한 부하에서 최적 성능을 내고 병목을 사전에 방지한다.
- 유지 보수성: 향후 유지 보수와 업데이트가 쉬워 관리 비용을 줄이고 수명을 늘린다.
- 비용 효율성: 꼼꼼한 설계는 버그 가능성이 낮아 오류와 재작업을 줄인다.

## 1.4 시스템 설계의 중요성을 엿볼 수 있는 실제 사례

- 금융: 거래 내역과 고객 계좌를 다루므로 안전하고 신뢰성이 높은 시스템이 필요하다.
- 전자상거래: 대량 거래, 재고 관리, 배송, 고객 정보를 처리한다. 사용자 친화적이고 안전하며 확장 가능해야 한다.
- 의료: 전자 의료 기록과 의료 영상 시스템은 안전하고 신뢰성 있으며 규제 기준을 준수해야 한다.
- 제조업: 생산 공정 제어, 장비 모니터링, 재고 관리에 쓰인다. 통합적이고 효율적이며 신뢰성 있게 작동해야 한다.
- 운송업: 물류 관리, 배송 추적, 경로 최적화에 활용한다. 신뢰성과 안전성을 갖추고 대량 데이터를 처리해야 한다.

일상의 거의 모든 서비스는 탄탄한 설계 위에서 돌아간다. 좋은 설계는 프로세스를 자동화하고 성능을 최적화해 궁극적으로 더 나은 비즈니스 성과를 이끈다.

## 1.5 요약

시스템 설계는 시스템의 아키텍처, 컴포넌트, 모듈, 인터페이스, 상호 작용을 정의하는 일련의 과정이다. 상위 수준 아키텍처를 먼저 만들고 하위 수준의 상세 기능을 구현하는 방식으로 진행한다. 상위 수준 설계는 아키텍처, 데이터 흐름, 확장성, 장애 허용성을 다루고, 하위 수준 설계는 구현 세부와 특정 구성 요소에 중점을 둔다. 좋은 설계는 요구 사항의 명확한 이해, 협업, 확장성, 성능, 유지 보수성, 비용 절감을 보장한다.
