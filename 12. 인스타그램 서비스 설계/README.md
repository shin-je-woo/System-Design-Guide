# 12. 인스타그램 서비스 설계

인스타그램은 사진과 영상을 공유하며 소통하는 소셜 미디어 플랫폼이다. 여러 사용자가 만드는 방대한 콘텐츠를 확장성 있고 안정적으로 처리하면서 끊김 없는 경험을 줘야 한다. 이 장은 요구 사항과 데이터 모델, 규모 산정, 고수준 설계를 거쳐 사진 업로드, 뉴스 피드, 사용자 세 핵심 서비스의 세부 설계를 다룬다.

## 12.1 기능적 요구 사항

- **사용자 등록과 인증**: 이름과 이메일, 비밀번호로 계정을 만들고 인증 정보를 안전하게 저장하며 세션을 효율적으로 관리한다.
- **사진 업로드와 공유**: 기기에서 업로드하거나 촬영한 사진을 JPEG나 PNG로 받아 압축하고, 필터와 캡션, 태그를 더해 안정적인 저장소에 보관한다.
- **뉴스 피드**: 팔로우한 사람들의 사진을 업로드 시간과 관계, 참여도를 반영해 맞춤형으로 실시간 생성하고 무한 스크롤을 지원한다.
- **상호 작용과 메시지**: 좋아요와 댓글, 멘션을 지원하고, 사진과 메시지를 비공개로 주고받는 다이렉트 메시지를 실시간 알림과 함께 제공한다.
- **검색과 알림**: 사용자와 사진, 해시태그를 검색하고 트렌드와 추천을 탐색하며, 팔로워와 좋아요, 댓글, 메시지 이벤트를 푸시와 인앱 알림으로 전달하고 알림 옵션을 조정한다.

## 12.2 비기능적 요구 사항

- **확장성과 성능**: 서버를 추가해 수평 확장하고 사진 업로드나 뉴스 피드 같은 기능을 독립적으로 확장하며, 캐싱과 비동기 처리(압축, 썸네일 생성)로 빠른 응답을 유지한다.
- **가용성과 신뢰성**: 데이터 복제와 로드 밸런싱, 장애 허용성, 백업과 복구로 중단 없이 운영하고, 트랜잭션과 일관성 모델로 데이터 무결성을 지킨다.
- **사용성**: 검색과 필터, 추천 기능으로 콘텐츠를 쉽게 찾고 서비스를 적극 활용하게 한다.

## 12.3 데이터 모델 설계

- **주요 엔티티**: User, Photo, Comment, Like, Follow, Hashtag, PhotoHashtag, DirectMessage로 구성하며, 한 사용자가 여러 사진을 올리는 일대다와 사진과 해시태그의 다대다 관계를 담는다.
- **핵심 구조**: User는 user_id로 프로필을, Photo는 photo_id로 작성자와 캡션, 이미지 URL, 위치, 태그를 담는다. Comment와 Like는 사용자와 사진 ID를, Follow는 follower_id와 followee_id를 담고, Hashtag와 사진을 잇는 PhotoHashtag가 다대다 관계를, DirectMessage가 발신자와 수신자, 내용을 담는다.

## 12.4 시스템 규모 산정

- **규모 가정**: 전체 1억 명, 일간 활성 사용자 1000만 명, 1인당 하루 사진 2장, 사진당 5MB, 보관 5년, 평균 팔로워 500명, 사진당 좋아요 100개와 댓글 10개다.
- **저장소**: 사진은 5년간 약 182.5PB, 사용자 데이터는 약 100TB, 메타데이터는 약 36.5TB로 합계 약 182.5PB다.
- **대역폭과 처리**: 하루 사진 업로드 약 100TB에 팔로워 전송을 더해 하루 약 50PB이며, 초당 사진 업로드 약 230장, 좋아요 약 23,000개, 댓글 약 2,300개를 처리한다.

## 12.5 고수준 설계

- **진입 구조**: 클라이언트-서버 아키텍처에서 로드 밸런서가 트래픽을 분산하고, API 게이트웨이가 진입점으로 라우팅과 인증, 속도 제한을 처리한다.

#### 핵심 마이크로서비스

- **사진 업로드 서비스**: 사진을 처리하고 저장하며 이미지 압축과 크기 조정, 썸네일 생성을 수행하고 원본을 객체 저장소에 보관한다.
- **뉴스 피드 서비스**: 팔로우한 계정의 사진을 모아 순위 알고리즘으로 재배열한 맞춤 피드를 만들고 캐시로 응답을 높인다.
- **사용자와 상호 작용 서비스**: 사용자 서비스가 프로필과 인증, 권한을 다루고, 상호 작용 서비스가 좋아요와 댓글, 해시태그를 처리하며 알림을 보낸다.
- **다이렉트 메시지 서비스**: 비공개 메시지 전달과 저장, 실시간 업데이트를 아파치 카프카로 비동기 처리한다.

#### 공통 인프라

- **데이터베이스와 캐싱**: 관계형 데이터베이스에 프로필과 사진 메타데이터 같은 정형 데이터를 ACID로 저장하고, 카산드라나 MongoDB 같은 비관계형에 대량 쓰기와 실시간 데이터를 최종 일관성으로 다루며, 레디스로 자주 조회하는 데이터를 캐싱한다.
- **저장과 전달**: 사진과 동영상은 아마존 S3 같은 객체 저장소에 두고, CDN으로 사용자와 가까운 에지 서버에 캐싱해 지연을 줄인다.
- **비동기와 보안**: 사진 처리나 알림 같은 무거운 작업을 카프카와 백그라운드 프로세스로 비동기 처리하고, OAuth 인증과 해싱, 암호화, 속도 제한으로 보안을 확보한다.

## 12.6 서비스 세부 설계

#### 사진 업로드 서비스

- **API**: 사진을 올리는 `POST /photos`와 조회하는 `GET /photos/{id}`를 제공한다.
- **업로드 과정**: 요청을 검증하고 사진 ID를 만들어 메타데이터를 데이터베이스에 저장한 뒤, 원본을 객체 저장소에 올리고 압축과 크기 조정, 썸네일 생성을 카프카 메시지 큐로 비동기 요청한 다음 사진 ID와 URL을 반환한다.
- **비동기 처리**: 백그라운드 작업이 메시지 큐를 읽어 사진을 압축하고 여러 해상도 파일과 썸네일을 만든 뒤 데이터베이스의 파일 위치를 갱신한다.
- **조회와 전달**: 데이터베이스에서 URL을 포함한 메타데이터를 조회하고 객체 저장소에서 파일을 가져와 반환하며, CDN 에지 캐싱과 레디스 메타데이터 캐싱으로 조회를 빠르게 한다.

#### 뉴스 피드 서비스

- **API**: 맞춤 피드를 가져오는 `GET /newsfeed/{userId}`가 userId와 limit, offset을 받는다.
- **생성 과정**: 팔로우 관계를 확인해 팔로우한 계정의 최근 사진과 메타데이터를 수집하고, 업로드 시간과 친밀도, 참여도를 조합한 랭킹 알고리즘으로 정렬한 뒤, 페이지네이션 토큰으로 나눠 불러오고 캐시에 저장하며 중복 사진을 걸러 낸다.
- **실시간과 동기화**: 웹소켓이나 롱 폴링(long polling)으로 새 사진과 상호 작용을 실시간 전달하고 알림 서비스와 연동해 푸시를 보낸다. 여러 기기 간에는 마지막으로 본 사진의 타임스탬프 이후만 전송하는 타임스탬프 기반 동기화와 점진적 업데이트로 중복 없이 최신 내용만 불러온다.

#### 사용자 서비스

- **API**: 계정 생성 `POST /users`, 인증 `POST /users/login`, 프로필 조회와 수정 `GET/PUT /users/{id}`, 팔로우와 언팔로우 `POST/DELETE /users/{id}/follow`를 제공한다.
- **등록과 인증**: 회원 가입은 데이터를 검증하고 이름과 이메일 중복을 확인한 뒤 비밀번호를 해싱하고 user_id를 만들어 저장한다. 로그인은 자격 증명을 대조해 인증 토큰을 생성해 반환한다.
- **팔로우와 언팔로우**: 권한을 검증한 뒤 팔로우 테이블에 항목을 추가하거나 삭제하고, 양쪽 사용자의 팔로워와 팔로잉 수를 각각 증가시키거나 감소시킨다.
- **성능과 보안**: 레디스로 인기 사용자 프로필을 캐싱하고 알림과 뉴스 피드 서비스에 이벤트를 전달하며, 비밀번호를 bcrypt로 해싱하고 만료 시간을 둔 JWT 토큰과 암호화, 접근 제어로 보호한다.

## 12.7 기타 고려 사항

- **해시태그와 추천**: 해시태그를 별도 엔티티로 두어 사진과 다대다로 연결하고 캡션에서 추출하며, 취향과 활동을 바탕으로 개인화한 탐색과 추천을 제공한다.
- **스팸 방지와 지역화**: 봇을 이용한 의심 활동을 감지하고 머신러닝 이미지 분류로 부적절한 콘텐츠를 걸러 내며 신고와 차단을 지원하고, 다양한 언어와 지역 설정을 제공한다.
- **수익화와 관측**: 스폰서 콘텐츠와 광고, 상품 태그로 수익을 창출하고, ELK 스택이나 스플렁크로 로그를, 프로메테우스와 그라파나로 메트릭을, Jaeger나 집킨으로 분산 추적을 수집하며 임계 값 기반 자동 알림을 둔다.

## 12.8 요약

- **핵심 설계**: 사진 업로드, 뉴스 피드, 사용자 세 서비스를 중심으로 요구 사항과 데이터 모델, 규모 산정, 고수준 아키텍처를 다뤘다.
- **확장 기법**: 수평 확장과 데이터 파티셔닝, 분산 처리로 방대한 사진을 감당하고 캐싱과 CDN으로 응답 속도를 높였다.
- **고도화 방향**: 스토리와 라이브 스트리밍, 증강 현실 필터, 머신러닝 기반 추천과 객체 탐지, 소셜 커머스 통합으로 발전시킬 수 있다. 다음 장에서는 구글 독스 설계를 다룬다.
